## What the audit changed (draft → this plan)
1. **Pipe pause:** level 7's moving pipes already shift 86.6 px of the 91.5 px clearance rule (`tests/pipeMove.test.js`).
   - The draft's pause *inside* the cycle makes the travel steeper, so the rule breaks at every pause size: 98.4 px at a 0.12 pause, 108.3 px at 0.2.
   - **New design:** the pause is **added on top of** the swing (`pipeMove.holdMs` per end). The travel keeps its sine shape and peak speed, `pipeMoveShiftPx` and the clearance test stay as they are, and the average speed eases slightly.
2. **Username rules:**
   - **Client only** (Michael), so no schema step and no apply-before-push.
   - The draft's `validateName(raw, { mode })` would touch 13 call sites, including the board rows, user codes and the board-name adoption, all of which must keep accepting legacy names.
   - Instead, `validateName` stays the legacy 1–16 check, and a new `checkNewName` guards only the save panel's Save / blur.
   - Re-saving the name you already have (same name key) is always allowed: grandfathering.
3. **Play again would loop.** Phaser keeps a scene's last data (the same gotcha as the What's new bug fixed in 0.11.1).
   - With `scene.restart({ playAgain: true })`, every later plain `restart()` (Home, the field re-fit) would auto-start a run again.
   - **New design:** a one-shot registry flag `'playAgain'`, which Play's `create()` reads and clears.
4. **Over panel room:** the Share | Home row ends 66 px above the panel's bottom, and Home's halo reaches 40 px past it, so a third row does not fit. The panel grows **downward** only (its top, headline and score stay put) when Play again is shown.
5. **Share text:**
   - The draft's "keep the builders for API stability" would leave `dailyShareRank` and the share strings dead, which the orphan audit flags.
   - **New design:** `shareRun` sends `SHARE.url`. `shareText`, `dailyShareText`, `dailyShareRank` and their notes rows and tests go.
6. **Pulses:** `createButton` re-fits its label's scale on every `setText`, so a raw tween on the label would fight it.
   - **New design:** a `pulse(on)` method in `src/ui/button.js` that tweens around the fitted scale and refits on stop.
7. **Version:** 0.11.2 is taken → **0.12.0**.

## Steps

### Step 1/6: new usernames are cleaner; existing ones keep working  [done]
- **Change:**
  - `src/save.js`: `checkNewName(raw, { current = '' })` → `{ ok, name, reason }`.
  - Rules, in order, on the trimmed name:
    - `long`: over `NAME_MAX`;
    - `space`: any whitespace (`/\s/u`);
    - `emoji`: `/\p{Extended_Pictographic}|\p{Regional_Indicator}/u`;
    - `short`: under 4 code points, or under 2 if it holds a CJK character (`/[\p{Script=Han}\p{Script=Hiragana}\p{Script=Katakana}\p{Script=Hangul}]/u`);
    - `blocked`: contains a word from `NAME_BLOCKED`, a short explicit English list with no stems under 4 letters, matched lowercased.
  - A name whose key (lowercase, trimmed) equals `current` is always ok (grandfathered).
  - `validateName` is unchanged.
  - `src/ui/savePanel.js`: Save and the name check call `checkNewName(value, { current: state.name })`; a refusal shows its reason line.
  - i18n `saveNameRules.{short,space,emoji,blocked}` (en + zh-Hans, notes rows); `saveNameRequired` wording if it states 1–16.
- **Tests (`tests/save.test.js`):**
  - every reason, at its boundaries;
  - CJK 2 ok and 1 refused, Latin 3 refused;
  - a blocked word inside a longer name;
  - grandfathering: "best players A&G" and "💩" re-saved as their own current name are ok, but not as a new name;
  - `validateName` still takes all of them.
- **Smoke (`home`):** the save panel refuses "ab c" with the space reason and keeps the old name; a 4-letter name saves.
- **Commit:** `feat(save): new usernames: 4+ characters (2+ in CJK), no spaces, emoji or listed words; existing names keep working`
- **Result:** npm test 475/475; full smoke 365/365 (home: "ab c" and "Abc" refused with their reasons, the board never asked). The list leaves out words whose stems sit inside ordinary names (e.g. the one in Scunthorpe); the placeholder and the required line say 4–16.

### Step 4/6: moving pipes pause at each end of their swing  [pending]
- **Change:**
  - `src/config.js` `pipeMove.holdMs: 300` (per end; a knob).
  - `src/logic.js` `gapBobY(elapsed, baseY, amp, periodMs, phase, holdMs = 0)` runs rise → hold → fall → hold over a cycle of `periodMs + 2·holdMs`. Each travel half is the sine's own half-cycle (`−amp·cos`), so the peak speed equals today's.
  - With `holdMs = 0` it equals today's sine exactly (a test pins this).
  - `rollPipeMove` carries `holdMs`; every caller (pipes and pair-bob gap items, so a probiotic riding a moving gap pauses with it) passes it.
- **Tests (`tests/pipeMove.test.js`):**
  - the curve holds at ±amp for `holdMs`;
  - it is continuous at every joint;
  - its peak speed equals the sine's;
  - its zero-hold case equals the old formula;
  - the clearance test is unchanged and still passes.
- **Smoke (`levels` or `mystery`):** a moving pair sampled over a cycle sits within 1 px of ±amp for at least `holdMs − 1 frame` at each end.
- **Commit:** `feat(pipes): moving gaps pause at each end of their swing`

## Risks and notes
- **Substring blocklist false positives:** the list keeps to longer explicit words, and a test shows a plain name like "Scunthorpe" is not refused (no short stems).
- **Name rules are client-only:** a modified client can still post any 1–16 name (the server's CHECK and claim rules are unchanged). That is the same trust model as scores; README says so.
- **The pipe pause lowers the average gap speed slightly** (L5: 4.0 s swing → 4.6 s cycle with 300 ms holds). The per-level `speedPx` steps still set the swing itself.
- **Play again must not loop:** the registry flag is cleared before `launch`, and the smoke proves a later Home stays on the ready screen.
